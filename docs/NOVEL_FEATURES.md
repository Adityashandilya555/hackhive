# What hackhive adds beyond the organisers' spec

The organisers ask for a solver, a per-plan overlay, the slide-8 JSON and a final-presentation visual (`docs/SPEC_COVERAGE.md`). On top of that we build a small set of **novel features** chosen to impress judges cheaply.

**Rules every novelty follows** (Adi's brief):
- **It stays inside the problem statement.** It displays real solver output under the organisers' rules, or a clearly labelled what-if.
- **What-ifs are never submitted.** Only problem-statement results are written as `PLAN_*.json`.
- **It's low-effort:** size S or M, built on outputs the solver produces anyway.
- **It's earned:** each one shows a rule from the slides working, rather than adding decoration.

## 1. Frontend novelties (Streamlit app)

### 1.1 Arrangements gallery with filters (Adi's priority 1)
**What judges see:** every feasible way to split the plan into hub zones, as small multiples sorted by the organisers' ranking. Filters narrow it down:
- **hub count:** 2 / 3 / 4 …;
- **node cap:** 5, or the 20 what-if.

Click a tile to open the fully routed, checked design.

**Why it's novel and honest:** the list is **real exhaustive enumeration**, not a sample. Profiling all 17,000 ResPlan plans found at most 116 contiguous zonings per plan, enumerated in ≤ 16 ms. Each tile shows H, J and the checker's ✓/✗.

| Shows the rules | ranking H → J → area gap (slides 3, 6); contiguity and capacity (slide 3 rules 2-3) |
| Solver output used | `enumerate(plan, c)` → `Arrangement` list with checker metrics |

### 1.2 Optimality badge (priority 2)
**What judges see:**
- "**3 hubs · optimal (exhaustive search) · LB 2 (+1)** · J = …" when the hub count sits above the lower bound;
- "**2 hubs = lower bound**" when they're equal, the same line as slide 5;
- an expander that explains *why* the bound isn't reached: in star-shaped plans the living room acts as the hallway, which forces one-room zones.

**Why it's novel:** slide 5 only claims "k = lower bound". In 22% of plans that bound isn't reachable, and we **prove** the minimum instead.

### 1.8 Constraint sidebar: a locked "Problem statement" preset + labelled what-ifs
**What judges see:** the official rules shown as data and locked:

- hub ≥ 0.5 m from walls;
- 1 mm tolerance.

A what-if expander lets them change the caps, the J weights (the organisers call them "starting values") or the hub clearance. Any change raises a red **WHAT-IF** banner, and nothing from a what-if is ever submitted.

Ticking the box shows ResPlan's own reading, where those windows are doors (1 hub, WHAT-IF, never submitted).

## 2. Engine novelties (what makes the frontend honest)
| Novelty | Why it matters | Where |
|---|---|---|
| **A proven-minimum hub count.** Exhaustive enumeration of contiguous capped zonings, guarded above 16 rooms | Hubs are compared first; we never guess. In 22% of plans the minimum is above the lower bound, and we show why | #13, ADR-001 |
| **A mirror of the organisers' checker, with strict counting.** The six hard rules plus H, L, X, O, B and J at 1 mm; slide 7's 8 worked examples are unit tests; where the slides are ambiguous we count the stricter way | Our J is never below the organisers' J, so we never think a design is better than it scores | #11, #43, ADR-010 |
| **Never submit an invalid plan.** A checker gate, then a fallback to the next-ranked design, then to the walking skeleton | "An invalid or missing plan scores zero" (slide 6) | #16, #22, #23 |
| **J-optimal single-door handling.** Same-line retrace (counts as overlap) vs parallel runs (more bends), whichever J prefers. Example: a one-node ring of length d costs 3d + 1 retraced vs ≈ 2d + 2.2 parallel, so parallel wins for d > 1.2 m | Uses slide 7's "parallel runs don't count as overlap" legally | #21, ADR-005 |
| **Exact hub placement + ring order.** Every hub candidate (≥ 0.5 m from walls) × every node cycle, with lower-bound pruning; Held-Karp for the cap-20 what-if | Lowest J for the proven hub count | #20, ADR-002 |
| **Data-driven conventions.** Every edge-case rule was measured on all 17,000 ResPlan plans before it was decided (`docs/decision_conventions.md`) | No surprises on unseen plans: sliver rooms, doorless rooms, interior windows and the 36 plans with no possible hub spot are all handled | #4, #6, #9, #13 |

## 3. Two-minute demo script (S2-C)
1. **Problem statement preset.** Plan 5924 → the Best tab: the overlay with ids, the numbered rings and two parallel runs in a single-door room. The checklist is all ✓. The badge reads "3 hubs · optimal · LB 2 (+1)", and the expander explains the star topology.
2. **Step-through.** Drag the slider; ring H1 draws segment by segment back to its hub.
3. **Arrangements.** Plan 13344 → the gallery, filtered to 3 hubs; the Pareto chart shows why 3 hubs beats 4.
4. **Cap 5 vs 20.** Plan 13344: 3 hubs vs 1, with the cap-20 side marked "what-if, not submittable".
5. **What-if.** Raise the bend weight: a red WHAT-IF banner appears, and the routes change.
6. **Interior windows.** Plan 2814: tick the box and 2 hubs become 1 (what-if only).
7. **Batch.** The leaderboard shows 100% valid submissions on 100 unseen plans, plus the share at the lower bound.
8. **Download** the slide-8 JSON, the sidecar and the presentation image.

## 4. Deliberately not built
- **A "watch it route" live view** (Freerouting-style): zoning is instant, and the step-through gives the same effect. Freerouting is also GPL, so concepts only.
- **plotly / React:** no feature needs them (ADR-009).
- **Submitting any what-if:** the cap-20 mode, the interior-window reading and changed weights would break slide 3's rules or the organisers' weights.
